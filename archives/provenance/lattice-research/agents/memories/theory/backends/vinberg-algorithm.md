# Vinberg's Algorithm for Hyperbolic Lattices

## Project Goal

Implement a computationally efficient version of Vinberg's algorithm that, given a hyperbolic lattice presented as a Gram matrix with named generators, computes the simple roots whose orthogonal hyperplanes form the faces of the fundamental polytope.

## Mathematical Background

### The Group Γ

All three reference implementations (VinbergsAlgorithmNF, AlVin, vinal) target **W(L)**: the full hyperbolic reflection group generated by reflections in roots of L.

The control vector w determines which Weyl chamber becomes the fundamental polytope. Different choices of w yield polytopes that are **W(L)-equivalent**: if w' = g·w for some g ∈ W(L), then the corresponding fundamental polytopes are related by the same group element. The polytopes are in the same W(L)-orbit, not "isometric" in any intrinsic sense.

**Resolved**: The implementation targets W(L). The control vector is a parameter determining which chamber is returned, not which group.

### Input Specification

- A hyperbolic lattice L presented as a Gram matrix (n×n symmetric matrix over Z or a number field)
- Named generators e₁, ..., eₙ
- A control vector w (a timelike vector with (w, w) < 0; if not provided, a canonical choice must be made)

### Output Specification

- A collection of simple roots r₁, ..., rₘ expressed as linear combinations of the generators
- The Gram matrix of the simple roots (the Coxeter matrix)
- Sufficient data to reconstruct the fundamental polytope

### Phase 3: Algorithm Implementation

#### 3.1 Core Algorithm

All three reference implementations follow the same procedure:

**Input**: Gram matrix M (signature (n,1)), optional control vector w

```
1. DIAGONALIZE: Find timelike direction
   - vinal: NegativeVector() diagonalizes and extracts the negative-definite direction
   - VinbergsAlgorithmNF: diagonalize_and_get_scaling() with similar logic

2. INITIAL ROOTS (distance 0): Find roots orthogonal to w
   - Compute V1 = w^⊥ (positive-definite subspace)
   - Find all primitive roots r in V1 with (r,r) = k for possible root norms k
   - These form the "tip" of the polyhedral cone

3. ITERATE by increasing distance d(r) = |⟨w,r⟩|/√⟨r,r⟩:
   - Generate candidates as w_i + c·w where w_i ∈ V1 basis
   - Filter: must be root (integrality), ⟨w,r⟩<0, ⟨r_j,r⟩≤0 for all found roots
   - vinal: IterateRootDecompositions() uses bounding box enumeration
   - VinbergsAlgorithmNF: uses "stem" enumeration with T2-norm bounds

4. TERMINATE when polytope is complete:
   - vinal: coxiter check or cone dual verification
   - VinbergsAlgorithmNF: Lannér diagram and parabolic subdiagram conditions
```

**Key data structures** (from vinal.py):
- `V1`: w^⊥ as a positive-definite lattice
- `W`: integer points in the parallelepiped spanned by V1 and w
- `root_lengths`: possible norms for roots (divisors of 2·det(M)/gcd(adj(M)))

**Distance formula** (VinbergsAlgorithmNF:148-150):
```
fake_dist_to_point(w, r) = ⟨w,r⟩² / |⟨r,r⟩|
```
This is sinh² of the hyperbolic distance.

### Enumeration: Baseline (Naive) Algorithm

#### Diagonal/Level Enumeration

The most basic enumeration of ℤⁿ proceeds by **level** (L¹ norm):

```
Level s = |k₁| + |k₂| + ... + |kₙ|

Enumerate in order of increasing s:
s=0: (0,0,...,0)
s=1: permutations of (±1,0,...,0)      [2n points]
s=2: permutations of (±2,0,...,0), (±1,±1,0,...,0)
...
```

This is the standard diagonal/zigzag enumeration proving ℤⁿ is countable.

#### Level Bound vs. Norm Bound

For a Gram matrix M, the norm of a vector k ∈ ℤⁿ is:
```
(k, k)_M = kᵀ M k
```

To enumerate all vectors with M-norm in [lb, ub]:

1. **Compute eigenvalue bounds**: Find λ_min, λ_max (min/max eigenvalues of M)
2. **Derive L² bound**: From λ_min · ‖k‖₂² ≤ kᵀ M k ≤ λ_max · ‖k‖₂², get ‖k‖₂ ≤ √(ub/λ_min)
3. **Derive level bound**: From ‖k‖₁ ≤ √n · ‖k‖₂, get level S = ⌈√n · √(ub/λ_min)⌉
4. **Enumerate**: All points with level ≤ S, filter by M-norm

**Number of points at level s**: O(s^(n-1)) for large s.
**Total points up to level S**: O(Sⁿ).

### Solving Quadratic Diophantine Equations: xᵀMx = n

The core problem is finding integer vectors v with vᵀMv = n, where M is a symmetric n×n matrix, typically indefinite (hyperbolic signature).

#### General-Purpose Solvers

**PARI/GP (Denis Simon's qfsolve.gp)**

Functions for general quadratic forms over ℤ:
- `qfsolve(G)`: find a solution to xᵀGx = 0 over ℚ (isotropic vector)
- `qflllgram_indef(G)`: LLL reduction for indefinite forms, finds isotropic vectors
- `qfbsolve(Q, p)`: solve binary quadratic form Q(x,y) = p

Algorithm (qflllgram_indef):
1. Diagonalize blocks to create positive definite bounding form
2. Apply LLL reduction
3. Transform back and solve for isotropic vectors

**SageMath (via PARI backend)**
```python
from sage.quadratic_forms.qfsolve import qfsolve

# Find solution to x^T G x = 0 over Q
G = matrix(QQ, [[1,0,0],[0,-1,0],[0,0,1]])
qfsolve(G)  # Returns isotropic vector or indicates no solution
```

**Magma**
- `IsotropicSubspace(Q)`: find isotropic vectors for quadratic form Q
- `Solve(Q, n)`: solve Q(x) = n over integers
- `Representation(Q, n)`: find vector with Q(v) = n

#### Finding ALL Solutions for Given Norm

The problem of enumerating ALL solutions to vᵀMv = n (not just one) requires:

1. **Find one solution** (using solvers above)
2. **Parametrize the solution set** using the orthogonal group action
3. **Filter for integer solutions**

For indefinite forms, the solution set is typically infinite (hyperboloid), so enumeration must be bounded by additional constraints (e.g., distance from control vector).

#### Approach: Restrict to Positive-Definite Subspace

For Vinberg's algorithm, the key insight is:

- Roots orthogonal to the control vector w lie in w^⊥, which is positive-definite
- In this subspace, the equation vᵀMv = k has finitely many solutions
- Can use Fincke-Pohst/sphere enumeration restricted to w^⊥

**vinal's approach** (qsolve.py): Solve directly in V1 = w^⊥ coordinates:
```
Find v₁ ∈ V1 such that (a + v₁, a + v₁) = k
```
This becomes a positive-definite quadratic Diophantine equation in dim(V1) = n-1 variables.

**Vinberg's Algorithm as a Sequence of Integer Programming Problems**

The algorithm iteratively solves constrained enumeration problems. At each step, finding new roots requires integer vectors satisfying:

```
(v, v) = k          (fixed norm, k ∈ possible_root_norms)
(w, v) = -d         (distance constraint, d increases each iteration)
(v, rᵢ) ≤ 0         (acute angle with all previously found roots rᵢ)
v ∈ L               (integrality in the lattice)
```

**Reduction to IP**: For fixed k and distance bound D, this becomes:

```
Find v ∈ ℤⁿ:
  vᵀMv = k
  wᵀMv ≤ 0
  rᵢᵀMv ≤ 0  for all i
  lbⱼ ≤ vⱼ ≤ ubⱼ  (bounds from norm/distance constraints)
```

**Key observations**:
- The constraints are linear in v except for the quadratic norm condition
- The feasible region is the intersection of a quadric surface with a polyhedral cone
- Each "shell" of the algorithm adds more linear constraints (from newly found roots)

**IP formulation strategies**:

1. **Sequential feasibility**: At each distance level, solve IP to find all vectors with that exact distance, then filter by norm condition

2. **Bounded enumeration**: Use LP relaxations to obtain bounds on each coordinate, then enumerate integer points in the resulting box

3. **Constraint generation**: Start with few constraints, find candidate vectors, add violated constraints, iterate

**Cone and Polyhedral Methods**

The acute angle constraints (v, rᵢ) ≤ 0 define a polyhedral cone C. The problem becomes:

```
Find v ∈ C ∩ L such that (v, v) = k and (w, v) = -d
```

This suggests approaches from polyhedral geometry:

**Hilbert basis enumeration**:
- Compute Hilbert basis of cone C (minimal generating set of C ∩ L)
- Filter basis elements by norm condition
- Libraries: **Normaliz**, **4ti2**

**Lattice points in polyhedra**:
- Enumerate all integer points in C ∩ [box bounds]
- Filter by quadratic condition
- Libraries: **LattE**, **barvinok**

### Enumeration Details: Sophisticated Algorithms

**Both reference implementations enumerate candidates unboundedly by increasing distance.**

#### The Coordinate System: Diagonalization over K, NOT over ℤ

**Critical point**: A ℤ-quadratic form (lattice) is NOT generally diagonalizable over ℤ. It becomes diagonalizable only after passing to the field of fractions K = Frac(O_K).

The function `diagonalize` (util.jl:3-94) implements diagonalization over the field:
- Uses row/column operations with **division**: `M[i0,i].elem_in_nf // g.elem_in_nf`
- Computes transformation P such that P'GP = D (diagonal)
- P has entries in K (not necessarily in O_K)

**The two coordinate systems**:
1. **Canonical coordinates**: Elements of L expressed as vectors in O_Kⁿ (the original basis)
2. **Diagonal coordinates**: Same elements expressed in the K-basis that diagonalizes the form

The conversion between them involves the transformation matrix P and its inverse. A vector has "integral" diagonal coordinates (k₁,...,kₙ ∈ O_K) iff P·(k₁,...,kₙ)ᵀ has integral canonical coordinates.

**The scaling factors** (util.jl:199):
```julia
scaling = [abs(lcm_denominators(ring, [inverse[i,j] for j in 1:n])) for i in 1:n]
```
The i-th scaling factor sᵢ is the LCM of denominators in the i-th row of P⁻¹. For a diagonal coordinate vector with kᵢ ∈ sᵢ·O_K, the canonical representation may still be integral, but the check must be performed explicitly.

#### The Integrality Check: The Core of the Algorithm

This is the key theoretical point that was elided. The algorithm must verify at each step that the candidate vector is actually in the lattice.

**VinbergsAlgorithmNF approach** (vinbergs_algo.jl:679, 724):
```julia
integral(a_stem_can_rep) = all((ex(a_stem_can_rep[idx]) ∈ ring) 
                               for idx in vd.diago_vector_last_on_coordinates[j])
```

The check verifies that the canonical representation `P·(k₁,...,kⱼ)` has all entries in O_K.

**Optimization**: The code only checks certain coordinates (the "last on coordinates") because earlier coordinates were already verified in previous steps.

#### vinal's Different Approach: Direct Quadratic Diophantine Solving

The vinal implementation avoids diagonalization entirely. Instead:

1. **Roots_decomposed_into** (vinal.py:164-179) solves the equation directly in V1 coordinates:
   ```
   Find v1 ∈ V1 such that (a + v1, a + v1) = k
   ```
   
2. Writing v1 = g·x where g is the V1 basis, this becomes:
   ```
   (2·m1 + x^T·m2)·x = c
   ```
   where m2 = g^T·M·g is the Gram matrix restricted to V1 (positive definite), m1 = a·M·g, c = k - (a,a).

3. **qsolve.py** solves this positive-definite quadratic Diophantine equation:
   - Recursively enumerates integer solutions
   - Uses conjugate gradient to find the minimum of the quadratic form
   - Iterates coordinates from that minimum outward
   - The search is bounded because m2 is positive definite

**Key difference**: vinal works entirely in the original ℤ-lattice coordinates, while VinbergsAlgorithmNF works in diagonal coordinates and checks integrality.

#### VinbergsAlgorithmNF: Recursive Stem Extension

The core function `_extend_root_stem!` (line 576-745) works in diagonal coordinates:

```
function _extend_root_stem!(stem, root_length, constraints, j):
    # stem = [k₁, ..., k_{j-1}] ∈ O_K^{j-1} are fixed diagonal coordinates
    # root_length = l = (r,r) > 0
    # j = current diagonal coordinate to enumerate

    remaining_norm = l - Σ_{i<j} αᵢkᵢ²  # αᵢ = diagonal values of the form

    # Bound on |kⱼ| from conjugate conditions:
    #     |σ(kⱼ)| ≤ √(σ(remaining_norm/αⱼ))  for all σ: K → ℝ

    T2_bound = Tr(remaining_norm/αⱼ)  # bounds T₂(kⱼ)

    for kⱼ in short_t2_elems(O_K, 0, T2_bound):
        if satisfies_crystallographic_condition(kⱼ):
            if integral_canonical_coordinates(stem ∪ {kⱼ}):  # Check P·(k₁,...,kⱼ) ∈ O_Kⁿ
                if satisfies_affine_constraints(kⱼ, constraints):
                    stem[j] = kⱼ
                    _extend_root_stem!(stem, root_length, constraints, j+1)
```

The key check at line 724 (`integral(stem_can_rep_updated)`) verifies that converting the diagonal coordinates back to canonical coordinates gives an element of O_Kⁿ.

#### T₂ Enumeration: How O_K ≅ ℤᵈ is Enumerated

The function `short_t2_elems` (fields.jl:92-107):

```julia
function short_t2_elems(O, lb, ub):
    # O ≅ ℤᵈ with basis b₁,...,b_d
    trace = trace_matrix(O)  # T₂(x) = x^T · trace · x  (pos-def on ℤᵈ)

    # Standard lattice enumeration (Fincke-Pohst):
    lat = short_vectors(Zlattice(gram=trace), lb, ub)
    # lat = [(c, T₂(c)) for c ∈ ℤᵈ with lb ≤ T₂(c) ≤ ub]

    # Convert ℤᵈ coordinates to elements of O_K:
    return [Σᵢ cᵢ·bᵢ for (c₁,...,c_d) in lat]
```

**Fincke-Pohst algorithm** (sphere enumeration):
- Input: positive-definite quadratic form Q on ℤⁿ, bounds [lb, ub]
- Output: all v ∈ ℤⁿ with lb ≤ Q(v) ≤ ub
- Method: recursive coordinate-by-coordinate enumeration with bounds from Cholesky decomposition

| Aspect | VinbergsAlgorithmNF | vinal |
