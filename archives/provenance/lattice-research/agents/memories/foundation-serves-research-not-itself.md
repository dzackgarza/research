# The semantic foundation is necessary but not the final objective

The category tree, Sage-compatible vocabulary, typed objects, morphism surfaces, and
backend bridges are necessary because without them agents drift into worthless
"research":

- reinventing standard Sage/GAP algorithms;
- constructing huge matrices by hand;
- writing inscrutable oracle code;
- claiming correctness from one-off computations;
- producing code that cannot be read as a mathematical argument.

But the foundation is justified only while it creates usable mathematical language.

## A foundation task is real when it

- adds or corrects a public mathematical noun, operation, morphism, invariant, or
  constructor;
- places an obligation in the correct category/class;
- makes a future computation auditable in standard mathematical vocabulary;
- exposes an exact backend capability through a clear interface;
- removes a concrete blocker to lattice/Coble research.

## A foundation task is suspect when it

- only rearranges cards, labels, handoffs, reports, or ledgers;
- expands category/spec surfaces without a downstream mathematical use;
- improves engineering neatness without improving mathematical semantics;
- makes QC numbers better by weakening or distorting mathematics;
- adds process gates that delay the next real mathematical construction.

## New code

`GOAL.md` is explicit: new code should mostly provide categorical interfaces, coercions,
validation, and bridge boundaries, not reimplement mathematical kernels.
