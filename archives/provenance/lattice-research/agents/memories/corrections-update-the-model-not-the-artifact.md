# Rule: A correction means the mental model is wrong

When the user corrects a repo/mathematical claim, do not immediately edit memories, scrub text, apologize, or produce a new artifact.

First identify the corrected claim exactly.

Then read the source evidence that decides it.

Then state the corrected model in operational form:

- What did I believe?
- What source fact disproves it?
- What is the corrected repo/mathematical model?
- What concrete action changes because of that correction?

Only after this may you edit a memory or artifact.

Never delete the evidence of a misunderstanding while leaving the misunderstanding intact. That is laundering the artifact instead of correcting the model.

## Durable correction rule

When a user correction proves to be source-relevant, record or update durable memory immediately after the corrected source model is understood or fixed. Do not rely on chat history, current context, or a local artifact to carry the lesson.

The memory must preserve the object-level rule that prevents the same future mistake, not a narrative of the session. If the correction exposed a banned behavior that can be checked mechanically, add the mechanical guard as well.

Verification: a future agent can retrieve the memory by the affected topic and know what behavior is forbidden or required without reading the original chat.

If the correction is cross-cutting, update every affected governing memory instead of
creating a standalone correction note. The corrected model should surface naturally
when agents learn the repo, review work, check themselves, handle corrections, or work
in the affected category/spec area.

When a correction exposes a repo-purpose or architecture misunderstanding, record it as
a false-model/correct-model rule. Do not write a self-report about the agent's mistake,
and do not hide the correction in a task-local phase note. The durable destination is
the memory or guidance file that future agents already load for that repo concept.

If the user asks whether every nuance has been captured, audit the durable record
against the corrected model before answering. A complete capture must include:

- the positive model;
- the assumptions that make the model apply;
- the allowed implementation shape;
- the explicit forbidden substitutes;
- the verification question a future reviewer should ask.

If any item is missing, patch the governing memory first and answer only after the diff
shows the missing guidance was added.
