# Cards, ledgers, plans, handoffs, and reports are not the work

Artifacts are useful only when they route or preserve real mathematical/source work.
They are not themselves progress.

A card, ledger, report, memory, handoff, issue note, or decision document is justified
only if it does one of the following:

1. routes an already-understood source/math problem to the correct place;
2. records a real mathematical decision after the source and theory have been inspected;
3. preserves evidence that will otherwise be lost;
4. prevents a known repeated failure mode;
5. enables a concrete implementation/proof/spec step that is otherwise blocked.

If the artifact does not change what source file, mathematical definition, proof
obligation, backend bridge, or research computation happens next, do not create it.

A memory or doctrine note is also paperwork unless it is placed where it will route
future work. Do not dump cross-cutting lessons into a standalone historical or
conversation-specific file. Distribute them into the normal memories agents already
load for repo purpose, category-spec work, review, correction handling, and refinement.

## Red flags

- writing a plan before reading the relevant code or mathematics;
- creating a decision card before identifying the exact mathematical choice;
- updating a ledger instead of fixing the source-level issue it points to;
- producing a handoff because the agent feels uncertain;
- expanding task trees while no mathematical object or implementation changes;
- using internal phrases such as "gate," "lane," "surface," "audit," or "frontier"
  without naming the actual object, method, theorem, source, or obstruction.
- creating a new all-purpose doctrine document instead of updating the existing
  source-of-truth memories that govern the affected behaviors.

When in doubt, delete or compress paperwork rather than produce more.
