# Handling Corrections

A correction is evidence that the current model is wrong.

Do not respond first with apology, agreement, memory editing, or a new plan.

## Required sequence

1. Identify the exact corrected claim.
2. Read the source evidence that decides it.
3. Replace the model, not the wording.
4. Apply the corrected model to the concrete task.
5. Edit memories only after the source issue is understood or fixed.

## Rules

- If the user asks "why," answer from source evidence. Do not speculate.
- If the user says you are documenting instead of fixing, stop producing artifacts and
  work on the source problem.
- If the correction exposes a mathematical misunderstanding, do not continue with work
  that depends on that mathematics until the corrected model is stated operationally.
